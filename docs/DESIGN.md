# 1차 강화 시스템 설계

이번 범위는 창·확률·비용·실패 처리와 단계 저장입니다. 능력치 변경, 수리 버프 덮어쓰기, 강화 단계 이름 표시는 보류했습니다.

## 처리 흐름

1. 클라이언트가 SPT 4.1의 `ItemUiContext.GetItemContextInteractions` 뒤에 동적 메뉴 한 항목을 추가합니다. 게임 API 접근은 `GameBridge`에 모아 이름·시그니처가 바뀌면 오류를 남기도록 했습니다.
2. 창을 열면 기존 인벤토리 작업 큐를 비운 뒤 `/rf/gear-enhance/quote`에 아이템 ID와 현재 F12 설정을 보냅니다. 통신은 기존 SPT `RequestHandler`를 사용합니다.
3. 서버는 자신의 PMC 프로필에서 소유·창고 위치·분류·내구도·잠금·빈 보관칸을 검사하고 본체 가격·현재 단계로 비용을 계산합니다. 클라이언트가 계산한 비용이나 주사위 값은 받지 않습니다.
4. 서버는 프로필마다 60초 견적 하나와 장비·부착물 상태의 지문을 보관합니다. 새 견적을 요청하면 이전 견적은 무효가 됩니다.
5. 실행은 커스텀 `GearEnhance` 아이템 이벤트를 게임의 `SendOperationRightNow`로 보냅니다. 서버가 견적·단계·장비 상태·소지 루블·파괴 확인을 다시 검사한 뒤 암호학적 난수로 판정합니다. 검사를 통과하기 전에는 비용을 차감하지 않습니다.
6. 루블 묶음의 차감·삭제 및 파괴는 SPT의 `InventoryHelper`를 사용합니다. 내구도 변경은 일반 아이템 변경 응답에 담습니다. 클라이언트는 기존 SPT 인벤토리 응답 처리 경로로 변경을 받습니다.
7. 결과와 단계는 프로필 최상위 추가 데이터 `rfGearEnhance`에 넣습니다. 별도 기록 파일과 프로필 사이의 저장 시점 차이를 만들지 않습니다. 재로드 시 SPT `JsonUtil`의 동일한 변환기로 복원합니다.
8. 클라이언트는 콜백 후 `/rf/gear-enhance/receipt`로 해당 견적의 결과를 조회합니다. 실행 응답이 시간 초과되면 자동 재시도하지 않으며 재접속 확인을 안내합니다.

## 적용 범위와 제한

- F12 설정은 이 싱글플레이어 모드의 사용자 설정입니다. 견적마다 서버에서 범위를 검증하지만 관리자 인증 정책은 제공하지 않습니다. 다중 사용자·Fika 환경을 지원한다고 주장하지 않습니다.
- 원본 아이템 템플릿은 수정하지 않습니다. 성공은 단계 기록만 바꾸며 기존 수리 버프를 건드리지 않습니다.
- 파괴는 SPT의 기본 삭제 의미를 따라 장착 부품·탄약·보험까지 제거합니다. 장비 안의 일반 보관칸에 물건이 있으면 먼저 비워야 합니다.
- 내구도 0은 현재값만 바꿉니다. 장비와 내구도 있는 부품·방탄판을 함께 처리하며 최대 내구도는 유지합니다.
- 기록은 아이템 ID에 종속됩니다. 다른 아이템으로 교체·분해·재조합되는 경우 자동 이전하지 않습니다.
- 반복 요청 방지는 현재 유효 견적의 일회성 소비와 최근 결과 확인을 함께 사용합니다. 결과 기록 100개를 넘긴 옛 요청도 유효 견적이 없으므로 다시 실행되지 않습니다.
- 일반 SPT의 프로필 저장 주기를 사용합니다. 서버 프로세스 강제 종료나 저장 장치 장애에 대한 별도 복구 저널은 제공하지 않습니다.
- 서버의 기존 다른 인벤토리 이벤트와 공유하는 외부 잠금은 없습니다. 클라이언트는 기존 작업을 먼저 비우고 실행 중 입력을 차단하며 서버는 실행 직전에 소유·상태·잔액을 다시 검사합니다.

## 파일 구성

| 위치 | 역할 |
|---|---|
| `src/Client/Plugin.cs` | F12 설정·강화 창·확인·실행 상태 |
| `src/Client/GameBridge.cs` | 게임 메뉴·세션·SPT HTTP 연결 |
| `src/Server/EnhanceService.cs` | 견적·검증·판정·기록 |
| `src/Server/SptEnhanceBackend.cs` | SPT 소유·가격·차감·삭제 서비스 연결 |
| `src/Server/Routes.cs` | 조회 라우트와 네이티브 아이템 이벤트 |
| `src/Shared/Contracts.cs` | 설정과 요청 결과의 공통 형식 |
| `tests/` | 실제 SPT 모델·삭제 도우미를 사용한 자동 검사와 게임 API 메타데이터 검사 |

다음 단계의 강화 효과는 별도 설계해야 합니다. 게임 수리 버프를 사용할 경우 중첩·수리 후 덮어쓰기·내구도에 따른 해제 조건을 먼저 확인해야 하며, 템플릿 전체를 바꾸면 다른 모든 동일 장비에 효과가 퍼질 수 있으므로 아이템 단위 적용 경로를 검증해야 합니다.
