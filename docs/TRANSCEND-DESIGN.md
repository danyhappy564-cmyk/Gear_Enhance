# 초월강화 설계 (1.3.0 예정)

2026-10-24 사용자 기획 + 확정 사항. 아직 구현 전. 숫자는 모두 F12 개발자 옵션(비밀번호 잠금)으로 조절 가능하게 만든다.

## 0. 확정된 사용자 결정

| 항목 | 결정 |
|---|---|
| 발사속도 | 단계당 `+50`과 `원래 발사속도의 6%` 중 작은 값 |
| 방어등급 | 3단계 +1클, 5단계 +2클, 최대 6클. 이미 6클이면 둔탁상 감소로 대체 |
| 실패 규칙 | 파괴 없음. 1~3단계 시도는 비용만, 4~5단계 시도는 실패 시 1단계 하락(하락 방지 가능) |
| 재료·천장 | 둘 다 채용. 재료는 설계자가 정함(아래 4절) |
| 2성 방어구 | 최대 내구도 증가가 맞음 |
| 추가 기능 | 3절 전부(재료·천장·초월 표식·초월 전용 창·실패 규칙·F12 수치) |
| 수평 반동 범위 (조사 후) | **B** — 뒤로 차는 힘(화면 `수평 반동`) + 좌우 튐 각도를 같은 %로 |
| 내구도 초과 방어력 +약4% (조사 후) | 사용자 위임 → **그대로 둠**(막지 않음) |

## 1. 구조

- 초월은 기존 강화 위의 **별도 트랙 2개**: `2성 초월`(★★ 이상), `3성 초월`(★★★). 각 0~5단계, 서로 독립.
- 초월 효과는 **스타 배율(×2/×3)을 받지 않는다**(효과가 곱해져 폭주하는 것 방지, 표시도 단순).
- 방어구 초월 효과는 기존 규칙대로 **등록된 방탄판·내피·바이저에도 적용**(1.2.0 방탄판 등록과 같은 방식).

## 2. 효과

### 2성 초월 (★★ 이상)

| | 효과 | 단계당 | 5단계 |
|---|---|---|---|
| 총기 | **수평 반동 억제** | 수평 반동 -6% | -30% |
| 방어구 | **최대 내구도 증가** | 최대 내구도 +6% | +30% |

- 총기: 수평 성분만 줄인다. 기존 `반동 제어`·스타와 합친 수평 감소 상한은 80% 유지(레이저 총 방지).
- 방어구: 아이템의 실제 최대 내구도를 올린다(수리 후에도 유지). 지킬 규칙:
  - 올린 양은 `템플릿 원래 최대치 × 6% × 단계`. 상태에 부품별 `부여량`을 기록해 두고, 여러 방어구에 등록된 부품은 **가장 큰 값 하나만**(합산 금지).
  - 강화 소멸(보험 실패·미가입), 등록 해제, 초월 하락 때 부여량만큼 되돌린다(현재 내구도는 새 최대치를 넘지 않게 자름).
  - 상인 +0 반환 장비는 부여량을 빼고 보낸다.
  - 방탄판 바꿔 끼우기로 최대 내구도를 "농사"하지 못하게, 새 부품은 등록(차액 규칙 그대로)해야 받는다.

### 3성 초월 (★★★)

| | 효과 | 단계별 |
|---|---|---|
| 연사 가능 총기 | **발사속도** | 단계당 `min(+50, 원래 발사속도 × 6%)`, 5단계에 최대 약 +30% |
| 반자동·볼트액션 | **고장·과열 감소**(대체) | 고장 확률 -10%/단계(최대 -50%), 과열 증가 -8%/단계(최대 -40%) |
| 방어구 | **방어등급 + 둔탁상 감소** | 1단계 둔탁상 -5%, 2단계 -10%, **3단계 +1클**·-15%, 4단계 -20%, **5단계 +2클**·-25%. 부품마다 원래 등급 + 보너스, 최대 6클 |

- 이미 6클인 부품: 등급 대신 둔탁상 추가 감소(+1클 대신 -10%, +2클 대신 -20%).
- 검사 화면 등급·발사속도 표시도 같은 값으로 바꾼다(표시와 실제가 달라지지 않게).
- 연사 가능 여부는 총의 발사 모드 목록으로 판정한다(연사 모드가 하나라도 있으면 발사속도).

## 3. 진행 규칙

### 성공률 (기본)

| 시도 | 2성 초월 | 3성 초월 |
|---|---|---|
| →1 | 60% | 40% |
| →2 | 50% | 30% |
| →3 | 40% | 20% |
| →4 | 30% | 15% |
| →5 | 20% | 10% |

### 천장

- 실패할 때마다 그 트랙의 다음 성공률 +5%p(2성) / +3%p(3성), 최대 +30%p. 성공하면 0으로 초기화. 하락해도 쌓인 값은 유지.
- 장비별·트랙별로 저장, 창에 `천장 +15%p`처럼 표시.

### 실패

- →1~→3 시도 실패: 비용·재료만 소모.
- →4~→5 시도 실패: 그 트랙 1단계 하락. `단계 하락 방지` 체크 시 하락 없음(추가 비용 = 기존 하락 방지 계수 공식).
- 파괴 없음.
- 비트코인 성공률 상승(+5%p, BTC 3개 + 100만 ₽)도 쓸 수 있음.

### 비용

- 루블: `최대(최소액, 본체 기준가 × 비율 × 1.5^(단계-1))`. 최소액 2성 100만 / 3성 300만, 비율 2성 50% / 3성 100%(방어구는 본체 + 등록 부품 가격). 1회 상한 1억.
- 재료: 4절. 성공·실패 모두 소모. F12 `재료 요구` 끄기 가능(개발자 옵션).

## 5. 화면

- **초월 창**: 진화 창처럼 별도 창(760×910). 강화 창 머리줄에 `초월` 버튼(★★ 이상일 때만). 탭 `2성 초월` / `3성 초월`(★★★ 전에는 잠김 표시).
- 창 내용: 현재 → 다음 단계, 현재/다음 효과, 성공률(기본 + 천장 + BTC), 재료 목록(보유/필요, 충분하면 초록·부족하면 빨강), 루블 비용, 하락 방지 체크(4~5단계 시도만), 실패 안내, 결과 화면.
- **초월 표식**: 창고 이름 옆에 청록색 `초월 N`(N = 두 트랙 단계 합 0~10), 칸 배경도 옅은 청록. 기존 금·보라·빨강 표식과 함께 표시.
- 효과음: 기존 진화 음원 재사용.
- 색: 1.2.0 규칙 유지(초록 좋음·주황 주의·빨강 손실) + 초월 청록.

## 8. 남은 위험

- ~~수평 반동만 따로 줄이는 지점이 없으면~~ → 있음(9.1). 좌우 각도 감소는 대체안이 아니라 함께 쓸지 결정 사항(9.4 질문 1).
- 발사속도 변경이 애니메이션·소리와 어긋나면 대체안: 연사 반동 누적 감소. 코드상 발사 간격은 타이머, 연사음 높낮이는 과열 비율만 써서 어긋날 가능성은 낮음(미검증).
- 최대 내구도 부여/회수는 수리·판매·보험 경로가 많아 버그 위험이 가장 크다. 조사 결과 실제 최대치 방식으로 갈 수 있으나 판매가 상승을 막아야 한다(9.2). 그래도 문제가 크면 "추가 내구도(첫 N만큼 피해 흡수)"로 대체.
- 봇은 강화를 받지 않으므로 플레이어 쪽으로 힘이 기운다(오프라인 전제).
- 짧은 속성 함수(`ArmorClass`, `FireRate`)를 바꾸는 방식은 게임이 그 함수를 호출 자리에 펼쳐 넣으면(인라인) 안 먹을 수 있다. 같은 방식인 기존 기동성 패치·Realism 발사속도 패치가 쓰이고 있어 위험은 낮다고 보지만, 3단계 첫 인게임 확인 항목으로 둔다.

## 9. 1단계 조사 결과 (2026-10-24, 게임 `Assembly-CSharp.dll`·SPT 4.1.6 서버·Realism 클라 `7e7ee34`)

판정: **가능** = 걸 지점이 하나로 정해지고 비용 O(1) / **어려움** = 되지만 부작용 처리 필요 / **불가** = 없음. 직접 게임에서 본 것은 없다(전부 코드상, 미검증).

### 9.1 효과별 적용 지점

| 효과 | 게임이 계산하는 곳 | 바꾸는 방법 | 도는 빈도 | 판정 | Realism 같이 쓸 때 |
|---|---|---|---|---|---|
| 수평 반동(뒤로 차는 힘) | `NewRecoilShotEffect.RecalculateRecoilParamsOnChangeWeapon`(무기 반동 값 다시 계산) → `BasicPlayerRecoilPositionStrength` = 템플릿 `RecoilForceBack` × 강화 배율 | 계산이 끝난 값에 `(1-감소율)` 곱 | 무기를 들 때·부착물 바뀔 때만 | 가능 | Realism도 같은 칸을 자기 식으로 채운 뒤라 그 위에 곱해짐 |
| 좌우 튐 각도 | `CalculateBaseRecoilParameters`(반동 방향 범위 계산) → `BasicPlayerRecoilDegreeRange` = 각도 ± `RecolDispersion` | 범위 폭을 가운데 기준으로 `(1-감소율)` | 무기를 들 때 | 가능 | 위와 같음(Realism은 앞에서 대체, 우리는 뒤에서 곱함) |

| 발사속도(연사·점사) | `Weapon.FireRate` 속성 → 연사 간격 `60/FireRate`(`AutomaticFireOperation`) | 속성 결과에 `+min(50, 결과×6%)` | 연사 시작·과열 변화 때 | 가능 | Realism도 같은 속성을 바꿈(탄약 따라). 우리 값이 그 위에 더해짐 |
| 발사속도 화면 표시 | 무기 속성 `FireRate`가 템플릿 `bFirerate`를 직접 읽음 | 위 표시 교체와 같은 방식 | 동기화 때 | 가능(중간) | — |
| 연사 가능 판정 | `Weapon.WeapFireType`(발사 모드 목록)에 `fullauto`(또는 `burst`) | 목록 검사 | 견적·동기화 | 가능 | — |
| 고장 확률(반자동·볼트) | `Player.FirearmController.GetTotalMalfunctionChance` | 결과(와 출력값)에 `(1-감소율)` | 매 발사(봇 포함) → 사전 조회 1번 | 가능 | Realism도 패치함. 결과 뒤에 곱하므로 적용 |
| 과열 증가 | `Weapon.GetShotOverheat`(한 발당 과열) | 결과에 `(1-감소율)` | 매 발사 | 가능 | — |
| 방어등급 | `ArmorComponent.ArmorClass` 속성 하나를 관통 판정·화면 숫자·아이콘·수리비가 모두 읽음 | 결과에 `+보너스`, 6 상한 | 피격·화면 | 가능 | Realism 탄도도 이 속성을 읽어 같이 적용. **Realism은 10등급 체계**라 6 상한이 안 맞음(9.4) |
| 둔탁상 | `ArmorComponent.ApplyDamage` 안에서 `Template.BluntThroughput`을 직접 읽음(속성 아님) | 그 읽는 자리만 우리 함수로 바꾸는 코드 치환(기존 페널티 표시와 같은 기법) | 피격 | 가능 | **Realism 탄도를 켜면 ApplyDamage를 통째로 대체**해 치환이 안 먹음 → 3단계에서 "끝난 피해에 곱하기" 방식도 같이 시험 |
| 최대 내구도 | 서버 아이템 `upd.Repairable.MaxDurability` | 강화 응답의 변경 아이템으로 전달(기존 "내구도 0" 실패 처리와 같은 경로) | 강화 때 | 어려움(9.2) | Realism은 내구도 비율을 대부분 100%로 자름 → 효과는 "더 오래 버팀"만 |

- 클라이언트는 게임 DLL을 직접 참조하지 않고 이름으로 찾는 방식이라, 새 패치도 기존 `StatPatches`처럼 이름·인자 개수로 찾고 없으면 시작 때 오류를 띄운다.
- 무기 반동 두 지점은 매 발사가 아니라 무기 교체 때만 돌아 비용 걱정이 없다. 매 발사·피격 지점(고장·과열·등급·둔탁상)은 동기화 때 만든 "아이템 ID → 초월 값" 사전 1번 조회만 한다(새 루프 금지, REGRESSIONS P3).

### 9.2 최대 내구도 부작용

| 경로 | 코드상 동작 | 처리 |
|---|---|---|
| 수리(상인·수리 키트) | 서버 `RepairHelper`, 클라 `ArmorRepairStrategy` 모두 아이템 자기 최대치 기준 | 올린 최대치 유지. 수리 마모는 최대치에 비례해 조금 더 깎임(그대로 둠) |
| 상인 판매가 | 클라 `PriceCalculator`: 기본가 × (최대치 ÷ 원래 최대치) | **그대로 두면 +30%까지 비싸게 팔림 → 막는다**: 부여량이 있는 아이템은 원래 최대치로 계산 |
| 플리·펜스 가격 | 서버 `ItemHelper` 품질 = √(내구도 ÷ 원래 최대치), 상한 없음 | 같은 이유로 서버 쪽도 원래 최대치로 자름 |
| 관통 판정 | `RealResistance`: 내구도 ÷ 원래 최대치 × 100, 상한 없음 | 130%면 실효 방어력 약 +4%(다 찬 상태 기준). 9.4 질문 2 |
| 화면 막대 | 범위가 0~원래 최대치 | 넘친 부분은 막대에 안 보이고 숫자만 큼(꾸밈 문제, 그대로 둠) |
| 보험·우편 반환 | 잃은 시점 아이템 그대로 저장 | 강화 보험 성공은 그대로, 상인 +0 반환은 부여량을 빼고 보냄(설계 2절) |

### 9.4 사용자 결정 (2026-10-24 확정: 1 = B, 2 = 그대로)

1. **수평 반동 범위**: (A) 게임 화면 `수평 반동` 수치(뒤로 차는 힘)만 / (B) A + 좌우 튐 각도도 같은 %로. 추천 B — A만 하면 숫자는 줄어도 좌우 흔들림 체감이 작다.
2. **최대 내구도 초과분의 방어력 +약 4%**: 그대로(추천, 작고 자연스러운 결과) / 100%로 잘라서 막기.
3. (기본값으로 진행할 것) 판매가 상승은 막는다. 점사 가능 총도 발사속도 대상. Realism 10등급 체계에서도 상한은 6클로 두고, 7클 이상 부품은 둔탁상 감소로 대체.
