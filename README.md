# 장비 강화 — Gear Enhance 0.4.0

SPT **4.1.6**용 클라이언트·서버 모드입니다. 창고의 무기·방어구를 우클릭하여 **장비 강화** 창을 열고, 강화할 항목·효과·확률·비용·실패 결과를 확인한 뒤 시도합니다.

0.4.0은 완성 보너스·보라색 표식, 무기 고위험 파괴/단계 하락, 1초 강화 게이지, 단계별 성공률·효과 곡선을 추가했습니다. **0.3.1의 창고 표시 오류 수정은 유지**합니다. 이번 버전의 실제 Unity 화면·연출·효과음은 아직 확인하지 않았으며 빌드·자동 검사와 구분합니다.

## 화면 구성

![승인된 강화 창 디자인 목업](docs/images/enhancement-mockup.png)

위 이미지는 실제 게임 캡처가 아닌 초기 설계 목업입니다. 현재 버전은 방향 선택 대신 각 항목을 따로 강화합니다. 전용 IMGUI 창에 실제 장비 아이콘, 항목 카드, 현재/성공 후 효과, 성공률·비용, 실패 안내를 표시합니다. 제목·설명은 중앙 정렬하며, 기본 창은 760×870이고 화면 크기에 맞춰 축소합니다.

## 강화 효과

무기는 **반동 제어·조작성·정밀성 3종**, 방어구는 **내구성·기동성 2종**을 각각 강화하고 모두 함께 적용합니다. 예를 들어 반동 +10인 무기에서도 조작성 +0을 따로 올릴 수 있습니다.

| 장비 | 항목 | 기본 최대 +10 효과 | 전 항목 완성 시 효과 |
|---|---|---|---|
| 무기 | 반동 제어 | 수직·수평 반동 15% 감소 | 18% 감소 |
| 무기 | 조작성 | 인체공학 +10 | +12, 무기 최종 인체공학 100 상한 |
| 무기 | 정밀성 | 탄·산탄 퍼짐 10% 감소 | 12% 감소 |
| 방어구 | 내구성 | 피격 시 내구도 소모 30% 감소 | 36% 감소 |
| 방어구 | 기동성 | 이동·회전·인체공학 페널티 20% 완화 | 24% 완화 |

**완성은 무기 3종 또는 방어구 2종이 모두 F12 최대 단계 이상인 상태**입니다. 기존 강화 효과에 기본 +20%를 더 곱하며, 다른 능력치를 새로 붙이는 방식은 아닙니다. 완성 장비는 보라색 배경과 `✦ 완성 +합계` 표식으로 구분합니다. 최대 단계를 올리거나 항목 단계가 내려가 완성 조건을 벗어나면 보너스도 해제됩니다.

초반은 같은 증가량, 절반 이후는 단계당 증가량이 1→4배가 되는 곡선입니다. 전체 증가량을 최대 단계에 맞춰 배분하므로 +10의 기본 효과는 위 표와 같습니다. 반동 +1~+5는 각각 약 0.79%p씩, 마지막 +9→+10은 약 3.16%p 증가합니다. **기존 단계는 유지하지만 중간 단계 효과도 새 곡선으로 다시 계산**하므로 이전 버전과 달라집니다.

| 시도 단계 | 기본 성공률 | 해당 단계 증가 배율 | 반동 감소 누계(완성 보너스 전) |
|---|---|---|---|
| +1 | 75% | 1배 | 0.79% |
| +2 | 70% | 1배 | 1.58% |
| +3 | 65% | 1배 | 2.37% |
| +4 | 60% | 1배 | 3.16% |
| +5 | 55% | 1배 | 3.95% |
| +6 | 50% | 1.6배 | 5.21% |
| +7 | 45% | 2.2배 | 6.95% |
| +8 | 40% | 2.8배 | 9.16% |
| +9 | 35% | 3.4배 | 11.84% |
| +10 | 30% | 4배 | 15% |

최대 단계를 바꾸면 곡선과 절반 기준도 함께 바뀝니다. 최대 효과 기준값은 `단계 기본값 × 최대 단계`와 효과 상한 중 작은 값이고, 완성 보너스는 그 뒤에 적용합니다. 최종 감소율은 80%, 인체공학 추가는 50을 넘지 않습니다.

효과는 해당 아이템 ID에만 적용합니다. 원본 템플릿·기존 수리 버프는 덮어쓰지 않습니다. 방탄판·바이저의 해당 항목은 가장 가까운 강화 부모 장비에서 상속하며 중첩하지 않습니다. 반동은 부착물 배율을 반영한 무기 성분에 적용하고 별도 카메라 반동은 대상이 아닙니다. 정밀성은 탄 퍼짐만, 내구성은 실제 내구도 소모만, 기동성은 음수 장비 페널티만 바꿉니다.

## 고위험 강화

기본 최대 +10에서 **무기 3개 항목이 모두 +5 이상인 상태에서 다음 강화를 시도하면** 고위험 규칙을 적용합니다. 최대 단계가 홀수이면 절반을 올림합니다(+9의 기준도 +5). 한 항목만 +5인 상태는 고위험이 아닙니다.

- 성공: 선택 항목 +1.
- 실패 중 25%: 본체·부착물·탄창·탄약 파괴, 보험과 강화 기록 제거.
- 실패 중 나머지 75%: 선택 항목만 -1, 다른 항목·장비 내구도 유지.
- 하락 후 한 항목이라도 절반 미만이면 일반 구간으로 돌아갑니다.

파괴 확률은 **실패한 경우 안에서의 비율**입니다. 세 항목 +5에서 +6을 시도하면 성공 50%, 파괴 12.5%, 단계 하락 37.5%입니다. 창에는 실패 중 파괴 비율과 이번 시도 전체의 파괴 확률을 함께 보여줍니다. 파괴 가능성이 있으면 기존 확인란을 체크해야 합니다. 항상 성공 옵션은 고위험 구간도 100% 성공입니다.

방어구는 일반 실패 설정을 따릅니다. F12에서 무기 고위험 강화를 끄거나 실패 중 파괴 확률을 0%(하락만)~100%(파괴만)로 조절할 수 있습니다.

## 사용 흐름과 진행 연출

1. 장착 해제한 장비를 창고에 넣고 내부 보관칸을 비웁니다.
2. 우클릭 → 장비 강화 → 강화할 항목을 선택합니다. 항목 선택에는 비용이 없습니다.
3. 단계·효과·성공률·비용·손실을 확인하고, 파괴 가능성이 있으면 확인란을 체크합니다.
4. 강화 시도를 누르면 **1초 동안 “강화 진행 중…”과 채워지는 게이지**가 표시된 뒤 서버에 판정을 요청합니다.
5. 서버 영수증으로 성공·하락·파괴 결과를 확인합니다. 서버 응답이 늦으면 게이지가 찬 상태로 기다립니다.

진행 중에는 중복 강화·항목 변경·새로고침을 막습니다. 설정 변경이나 창고 이탈은 전송 전 시도를 취소합니다. 게임 스레드를 멈춰 기다리지 않습니다. 견적은 60초 유효하며 만료되면 다시 불러옵니다. 결과 미확정 시에는 자동으로 재시도하지 않습니다.

일반 강화는 금색 배경과 `★ +전체 단계 합계`, 완성 장비는 보라색 배경과 완성 표식을 씁니다. 미확인·오류·충돌·장전 표시가 우선하며 표식 오류가 장비 생성을 중단하지 않도록 합니다. 성공은 금색, 완성은 보라색, 실패는 붉은색으로 미리보기가 잠깐 빛납니다. 파괴는 **강화 창 안의 장비 이미지 9개 조각이 흩어지는 연출**입니다. 게임 공간의 폭발 효과는 생성하지 않습니다.

시도·성공·실패·파괴는 서로 다른 게임 UI 소리를 사용합니다. 별도 음원이나 추가 모드는 필요 없고 F12에서 효과음을 끌 수 있습니다. 결과 연출과 결과음은 서버 영수증 확인 뒤에만 발생합니다. 아이콘·배경·스타일·타입 조회는 캐시하며 조각 연출에 새 텍스처나 GUI 좌표 회전을 사용하지 않습니다.

창을 닫으면 LogOutput.log에 Repaint CPU 평균·최대 시간을 한 번 기록합니다. 게임 전체 FPS나 GPU 시간은 아닙니다.

100% 성공도 비용을 소모합니다. 장착 중·레이드·상인 판매품·타인 아이템은 강화할 수 없습니다. 0.2.x의 단계는 기존 항목으로 무료 이전하고 다른 항목은 +0부터 시작합니다. 0.1의 단계만 남은 기록은 첫 항목에 기존 단계를 무료·100%로 복원합니다.

## F12 설정

BepInEx ConfigurationManager의 F12 → Gear Enhance에서 조절합니다. 설정 파일은 `BepInEx/config/rf.gearenhance.cfg`입니다.

| 설정 | 기본값 |
|---|---|
| 시작 성공률 / 단계별 감소 / 항상 성공 | 75% / 5%p / OFF |
| 항목별 최대 단계 | +10 |
| 기준 가격 | 북밸류(플리 기준가 선택 가능) |
| 비용 비율 / 단계별 비용 배수 / 최소 비용 | 10% / 1.25배 / 1,000 루블 |
| 일반 구간 실패 처리 | 비용만 소모 |
| 무기 고위험 강화 / 실패 중 파괴 확률 | ON / 25% (나머지는 선택 항목 -1) |
| 전 항목 완성 추가 효과 | +20% |
| 강화 효과음 | ON |
| 효과별 기본값 / 상한 | 반동 1.5/15, 인체공학 1/10, 정밀성 1/10, 내구성 3/30, 기동성 2/20 |

설정 변경은 기존 견적을 무효화하며 효과 설정은 기존 장비에도 적용됩니다. 최대 단계 변경은 효과 곡선·완성 판정·고위험 시작점에도 반영됩니다.

비용은 `최대(최소 비용, 본체 기준가 × 비용 비율 × 배수^선택 항목 현재 단계)`를 올림합니다. 1회 상한은 1억 루블이고 부착물 가격은 제외합니다. 기준가 10만이면 +0→+1은 1만, +1→+2는 12,500 루블입니다. 플리 가격은 SPT 템플릿별 기준가이며 없으면 북밸류로 대체합니다.

일반 실패 옵션은 KeepItem(비용만), ZeroDurability(현재 내구도 0·최대 내구도 유지), Destroy(본체·부착물·탄약 파괴), Downgrade(선택 항목 -1, 최저 +0)입니다. 무기 고위험 구간에서는 일반 옵션보다 파괴/하락 규칙이 우선합니다. 고위험 기능을 끄면 일반 옵션을 모든 단계에 적용합니다.

## 저장과 동기화

항목별 단계와 최근 100회 결과는 SPT 프로필 최상위 `rfGearEnhance.Tracks`에 아이템 ID별로 보관하며 일반 SPT 저장 주기를 사용합니다. 완성 보너스는 중복 저장하지 않고 현재 기록에서 계산하므로 재접속해도 누적되지 않습니다. 프로필 로드와 강화 후 서버 기록을 동기화하고, 기록 동기화가 실패하면 새 견적을 막습니다.

판매·분해·재조합으로 ID가 바뀌면 자동 이전하지 않습니다. 프로필 전환 시 캐시를 비웁니다. Fika·다중 사용자 환경은 지원 범위가 아닙니다.

## 빌드와 검사

필요한 도구는 **.NET SDK 10, 실제 SPT 4.1.6 설치본**입니다. Visual Studio에서는 .NET 10을 지원하는 버전을 사용합니다.

### Visual Studio에서 Release 빌드

1. 저장소 루트의 **`GearEnhance.sln`**을 엽니다. `tests/GearEnhance.Tests.csproj`만 열면 전체 패키징 프로젝트가 포함되지 않습니다.
2. 게임 경로가 기본값 `E:\SPT 4.1`과 다르면 `LocalSettings.props.example`을 `LocalSettings.props`로 복사하고 `SptRoot`를 실제 경로로 바꿉니다. 개인 경로 파일은 Git에서 제외합니다.
3. 위쪽 구성을 **Release**로 선택하고 **빌드 → 솔루션 빌드**를 누릅니다.
4. 성공하면 **`Build/GearEnhance-0.4.0.zip`**이 생성됩니다. 클라이언트·서버 DLL과 README·LICENSE만 포함하며 설치 경로 구조로 묶습니다.

`GearEnhance.Package` 프로젝트가 두 DLL의 빌드 완료 후 MSBuild로 압축합니다. Python이나 별도의 압축 프로그램은 필요하지 않습니다. 파일 변경이 없는 Release 빌드에서도 ZIP을 다시 생성하며, Debug 빌드에서는 생성하지 않습니다. 참조 전용 환경은 설치용 ZIP 생성을 차단합니다. **게임 폴더에 복사하거나 서버·게임을 실행하지 않습니다.** 클라이언트와 서버를 모두 0.4.0로 교체하고 서버·게임을 재시작해야 합니다. 통신 버전 3을 사용하며 0.3.x와 혼용하면 조회 단계에서 거절합니다.

명령줄에서도 같은 솔루션을 사용할 수 있습니다.

```powershell
dotnet build GearEnhance.sln -c Release
```

### 자동 검사까지 실행한 뒤 패키징

Python 3.12+가 있으면 기존 스크립트로 두 검사 모음까지 실행할 수 있습니다. Python 외부 패키지는 필요하지 않습니다. Visual Studio의 일반 빌드는 검사 프로젝트를 컴파일하며 검사를 자동 실행하지는 않습니다.

```powershell
python tools/build.py --spt-root "E:\SPT 4.1"
```

검사가 모두 통과한 뒤 Visual Studio와 같은 MSBuild 압축 대상으로 `Build/GearEnhance-0.4.0.zip`을 생성합니다.

클라우드의 컴파일 전용 참조 환경에서는:

```bash
source /workspace/.onboarding/dotnet-env.sh
GEAR_GAME_ASSEMBLY=/workspace/Cluade_For_spt/references/Assembly-CSharp.dll \
  python3 tools/build.py --spt-root /workspace/.gear-reference --validate-only
```

솔루션만 컴파일할 때는 `dotnet build GearEnhance.sln -c Release -p:SptRoot=/workspace/.gear-reference -p:GearCreatePackage=false`를 사용합니다. 이 옵션은 ZIP 생성을 생략하며 배포 빌드가 아닙니다.

단독 검사:

```text
dotnet test tests/GearEnhance.Tests.csproj -c Release
dotnet test client-tests/GearEnhance.ClientTests.csproj -c Release -p:SptRoot="E:\SPT 4.1"
```

`GEAR_GAME_ASSEMBLY`를 실제 `Assembly-CSharp.dll` 전체 경로로 지정하면 게임 API·계산 경로 대조 6개도 실행합니다. 경로가 없으면 이 6개만 생략하며, 클라이언트 검사에는 BepInEx의 실제 Harmony DLL이 필요합니다. 모든 복원은 고정한 lockfile을 사용합니다.
