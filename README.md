# 장비 강화 — Gear Enhance 0.3.0

SPT **4.1.6**용 클라이언트·서버 모드입니다. 창고의 무기·방어구를 우클릭하여 **장비 강화** 창을 열고, 강화할 항목·성공 후 능력치·확률·비용·실패 결과를 확인한 뒤 시도합니다.

이번 버전은 **항목별 독립 강화·효과음·금색 장비 표식을 추가한 개발판**입니다. 사용자 0.2.1 로그에서 견적·결과 조회 흐름을 확인했고, 깨진 아이콘과 창을 열 때의 프레임 저하 제보를 반영했습니다. **0.3.0의 실제 화면·효과음·표식·FPS는 재검증 전**이며 클라우드 빌드와 자동 검사 결과는 아래에 구분합니다.

## 화면 구성

![승인된 강화 창 디자인 목업](docs/images/enhancement-mockup.png)

위 이미지는 실제 게임 캡처가 아닌 초기 설계 목업입니다. **0.3.0은 방향 선택 대신 각 항목을 따로 강화**합니다. 전용 IMGUI 창에서 실제 장비 아이콘을 표시하며 게임 수리 창 프리팹은 복제하지 않습니다. 카드 제목·설명을 같은 중앙 축에 맞추고, 아이콘은 작은 텍스처로 한 번 만들어 재사용합니다. 기본 창은 760×870이며 화면 크기에 따라 축소합니다.

## 강화 효과

무기는 **반동 제어·조작성·정밀성 3종**, 방어구는 **내구성·기동성 2종**을 각각 강화합니다. 단계·최대 단계·비용 계산이 항목별로 독립되어 있고, 올린 효과는 모두 함께 적용됩니다. 예를 들어 반동 +10인 무기에서도 조작성 +0을 +1로 올릴 수 있으며 반동 +10은 유지됩니다.

| 장비 | 항목 | 단계당 기본 효과 | 기본 +10 효과·상한 |
|---|---|---|---|
| 무기 | 반동 제어 | 수직·수평 반동 1.5% 감소 | 15% 감소 |
| 무기 | 조작성 | 인체공학 +1 | +10, 무기의 최종 인체공학은 100 상한 |
| 무기 | 정밀성 | 탄 퍼짐 1% 감소 | 10% 감소 |
| 방어구 | 내구성 | 피격 시 내구도 소모 3% 감소 | 30% 감소 |
| 방어구 | 기동성 | 해당 장비의 이동·회전·인체공학 페널티 2% 완화 | 20% 완화 |

- 목업의 반동 제어 **+4: 6% → +5: 7.5%**를 그대로 적용합니다.
- 효과는 선택한 장비 ID에 연결하며 같은 종류의 다른 장비를 바꾸지 않습니다. 매 계산에 한 번만 곱하고 원본 템플릿이나 기존 수리 버프는 수정하지 않습니다.
- 반동 제어는 부착물 반동 배율을 반영한 무기 반동 성분에 적용합니다. 게임의 별도 카메라 반동·플레이어 스킬·전역 반동 보너스를 모두 같은 비율로 줄이는 기능은 아닙니다.
- 정밀성은 총알의 기본 탄 퍼짐과 산탄 패턴 퍼짐을 줄입니다. 조준 흔들림이나 탄도 낙차·탄속은 바꾸지 않습니다.
- 방어구 내구성은 총격·폭발로 차감되는 내구도를 줄입니다. 방어 등급이나 캐릭터가 받는 직접 피해는 바꾸지 않습니다. 본체의 효과는 장착된 방탄판·바이저에도 적용하며 중첩하지 않습니다.
- 기동성은 장비의 음수 페널티만 완화합니다. 다른 모드가 넣은 양수 보너스는 줄이지 않습니다.

## 사용 흐름

1. 장비를 장착 해제하고 창고에 넣습니다. 내부 보관칸에 일반 아이템이 있으면 먼저 비웁니다.
2. 우클릭 → **장비 강화** → 강화할 항목을 고릅니다. 다른 카드를 누르는 것에는 비용이 들지 않습니다.
3. 현재·성공 후 단계와 효과, 성공률, 비용, 보유 루블, 실패 결과를 확인합니다.
4. **강화 시도**를 누릅니다. 견적은 60초 동안 유효하며 만료되면 새로 불러옵니다.
5. 성공하면 선택 항목만 한 단계 올리고, 나머지 항목은 유지합니다. 실패하면 설정한 손실만 처리하며 모든 항목의 기존 단계는 유지합니다. 파괴 옵션은 본체와 부착물 전체 삭제입니다.

100% 성공도 비용을 소모합니다. 장착 중인 장비·레이드·상인 판매품·타인의 아이템에는 강화를 허용하지 않습니다. 창 뒤의 인벤토리 마우스 클릭을 차단하도록 구현했습니다.

**기존 기록 이전:** 0.2.x에서 반동 +5였다면 반동 +5를 그대로 유지하고 나머지 두 항목은 +0에서 시작합니다. 별도 이전 비용은 없습니다. 0.1.0의 효과 없는 단계만 남은 장비는 최초 한 번 해당 단계를 무료·100%로 한 항목에 복원합니다. 이후 다른 항목은 일반 확률·비용으로 강화합니다.

## 장비 표식과 효과음

강화된 장비에는 게임의 수리 특성 장비와 같은 **금색 배경**과 이름 뒤 **`★ +합계 단계`**를 표시합니다. 반동 +2·조작성 +1·정밀성 +3이면 `★ +6`입니다. 자세한 단계는 강화 창의 각 카드에서 확인합니다. 표식은 소유 아이템의 강화 기록으로 복원하며, 원본 수리 특성이나 아이템 템플릿을 바꾸지 않습니다. 미확인 아이템·오류·충돌·장전 상태의 원래 색상은 우선합니다.

강화 시도에는 장착 효과음, 성공에는 수리 완료음, 실패에는 오류음을 게임의 기존 UI 소리에서 재생합니다. 별도 음원이나 추가 모드는 필요하지 않습니다. F12의 **7. 피드백 → 강화 효과음**에서 끌 수 있으며 게임 소리 설정을 따릅니다. 결과음은 서버 영수증을 확인한 뒤 재생합니다.

## 창 성능과 화면 수정

0.2.1에서 아이콘 선이 창 밖으로 흩어지는 문제를 피하려고 아이콘별 GUI 좌표 회전을 제거했습니다. 48×48 아이콘 5개와 배경 격자는 최초 한 번 생성하고 재사용합니다. 매번 새 스타일 객체·라벨 내용을 만들던 부분도 정리했습니다. 창 유지 중 레이드 상태 확인이 호출하던 Harmony의 전체 타입 검색은 조회 결과 캐시로 대체했습니다.

창을 닫으면 `LogOutput.log`에 **강화 창 UI CPU: Repaint 횟수·평균·최대 시간**을 한 번 기록합니다. 이는 UI를 그리는 CPU 처리 시간이며 게임 전체 FPS나 GPU 시간은 아닙니다. **실제 FPS 개선 수치는 같은 게임 장면에서 다시 측정해야 합니다.**

## F12 설정

BepInEx ConfigurationManager가 설치되어 있으면 F12의 **Gear Enhance**에서 조절합니다. 파일은 `BepInEx/config/rf.gearenhance.cfg`입니다.

| 설정 | 기본값 |
|---|---|
| 성공률 / 항상 성공 | 75% / OFF |
| 항목별 최대 강화 단계 | +10 |
| 기준 가격 | 북밸류, 플리 기준가도 선택 가능 |
| 비용 비율 / 단계별 배수 / 최소 비용 | 10% / 1.25배 / 1,000 루블 |
| 실패 처리 | 비용만 소모 |
| 강화 효과음 | ON |
| 효과별 단계 증가량·상한 | 위 능력치 표와 같음 |

확률·비용 설정을 바꾸면 기존 견적을 무효화하고 새로 확인합니다. **효과의 증가량·상한은 이미 강화된 아이템에도 반영**하며, 들고 있는 무기와 장착 방어구의 계산값도 갱신하도록 연결했습니다. 이 실시간 갱신의 인게임 확인은 남아 있습니다. 최대 단계만 올려도 효과별 상한은 별도로 유지됩니다.

비용은 `최대(최소 비용, 본체 기준가 × 비용 비율 × 배수^선택 항목의 현재 단계)`를 올림한 값입니다. 1회 상한은 1억 루블이며 부착물 가격은 제외합니다. 기준가 10만 루블이면 +0→+1은 1만, +1→+2는 12,500 루블입니다. 플리 기준가는 SPT의 템플릿별 기준가이며 실시간 최저 매물가가 아닙니다. 가격이 없으면 북밸류로 대체하고 창에 표시합니다.

실패 옵션:

- `KeepItem`: 비용만 소모하고 장비·모든 항목 단계 유지.
- `ZeroDurability`: 본체와 내구도가 있는 부품의 현재 내구도 0. 최대 내구도·모든 항목 단계 유지.
- `Destroy`: 본체·부착물·탄창·탄약 삭제 및 보험 등록 제거. 별도 확인란이 필요하며 되돌리기는 없습니다.

## 저장과 동기화

각 항목의 단계와 최근 100회 결과는 SPT 프로필 최상위 `rfGearEnhance`에 아이템 ID별로 보관합니다. 0.3.0의 `Tracks`에 항목별 단계를 저장하고 0.2.x의 `Levels/Paths`는 한 번만 이전합니다. 별도 파일을 만들지 않으며 일반 SPT 프로필 저장 주기를 사용합니다. 프로필 로드 완료 시 서버에서 현재 소유한 장비의 기록을 받아 효과를 복원하고, 강화 후에는 서버 결과와 다시 동기화합니다. 읽기 전용 동기화를 완료하지 못하면 새 견적을 막아 서로 다른 모드 버전에서 잘못 비용을 내지 않도록 합니다.

판매·분해·재조합으로 아이템 ID가 바뀌면 자동 이전하지 않습니다. 프로필 전환 시 이전 캐시를 비우며 Fika·다중 사용자 환경은 지원 범위에 포함하지 않았습니다.

## 빌드와 검사

필요한 도구는 **.NET SDK 10, 실제 SPT 4.1.6 설치본**입니다. Visual Studio에서는 .NET 10을 지원하는 버전을 사용합니다.

### Visual Studio에서 Release 빌드

1. 저장소 루트의 **`GearEnhance.sln`**을 엽니다. `tests/GearEnhance.Tests.csproj`만 열면 전체 패키징 프로젝트가 포함되지 않습니다.
2. 게임 경로가 기본값 `E:\SPT 4.1`과 다르면 `LocalSettings.props.example`을 `LocalSettings.props`로 복사하고 `SptRoot`를 실제 경로로 바꿉니다. 개인 경로 파일은 Git에서 제외합니다.
3. 위쪽 구성을 **Release**로 선택하고 **빌드 → 솔루션 빌드**를 누릅니다.
4. 성공하면 **`Build/GearEnhance-0.3.0.zip`**이 생성됩니다. 클라이언트·서버 DLL과 README·LICENSE만 포함하며 설치 경로 구조로 묶습니다.

`GearEnhance.Package` 프로젝트가 두 DLL의 빌드 완료 후 MSBuild로 압축합니다. Python이나 별도의 압축 프로그램은 필요하지 않습니다. 파일 변경이 없는 Release 빌드에서도 ZIP을 다시 생성하며, Debug 빌드에서는 생성하지 않습니다. 참조 전용 환경은 설치용 ZIP 생성을 차단합니다. **게임 폴더에 복사하거나 서버·게임을 실행하지 않습니다.** 클라이언트와 서버를 모두 0.3.0으로 교체하고 서버·게임을 재시작해야 합니다. 이전 통신 형식은 새 견적 발행 전에 거절합니다.

명령줄에서도 같은 솔루션을 사용할 수 있습니다.

```powershell
dotnet build GearEnhance.sln -c Release
```

### 자동 검사까지 실행한 뒤 패키징

Python 3.12+가 있으면 기존 스크립트로 두 검사 모음까지 실행할 수 있습니다. Python 외부 패키지는 필요하지 않습니다. Visual Studio의 일반 빌드는 검사 프로젝트를 컴파일하며 검사를 자동 실행하지는 않습니다.

```powershell
python tools/build.py --spt-root "E:\SPT 4.1"
```

검사가 모두 통과한 뒤 Visual Studio와 같은 MSBuild 압축 대상으로 `Build/GearEnhance-0.3.0.zip`을 생성합니다.

클라우드의 컴파일 전용 참조 환경에서는:

```bash
source /workspace/.onboarding/dotnet-env.sh
GEAR_GAME_ASSEMBLY=/workspace/Cluade_For_spt/references/Assembly-CSharp.dll \
  python3 tools/build.py --spt-root /workspace/.gear-reference --validate-only
```

솔루션만 컴파일할 때는 `dotnet build GearEnhance.sln -c Release -p:SptRoot=/workspace/.gear-reference -p:GearCreatePackage=false`를 사용합니다. 이 옵션은 ZIP 생성을 생략하며 배포 빌드가 아닙니다.

단독 검사:

```text
dotnet test tests/GearEnhance.Tests.csproj -c Release
dotnet test client-tests/GearEnhance.ClientTests.csproj -c Release -p:SptRoot="E:\SPT 4.1"
```

`GEAR_GAME_ASSEMBLY`를 실제 `Assembly-CSharp.dll` 전체 경로로 지정하면 게임 API·계산 경로 대조 6개도 실행합니다. 경로가 없으면 이 6개만 생략하며, 클라이언트 검사에는 BepInEx의 실제 Harmony DLL이 필요합니다. 모든 복원은 고정한 lockfile을 사용합니다.

## 확인한 것과 남은 것

- 서버·클라이언트 빌드 경고·오류 0, **검사 71개 통과·생략 0**.
- 서버·공통 52개: 독립 강화·각각의 비용/실패·전체 파괴 정리·0.1/0.2 기록 이전·실제 SPT 프로필 저장/복원·중복 차감 방지·실제 DI 조회/실행 라우터 공유. 실제 게임 API 대조 6개는 효과 호출 경로와 금색 표식·효과음 연결을 포함합니다.
- 클라이언트 19개: 세 무기 효과 동시 적용·방어구 효과별 상속·원본 템플릿 보존·타입 캐시 1만 회 읽기의 추가 할당 0·아이콘 5종 경계/재현성·소리 선택·콜백과 상태 조회 등을 검사했습니다.
- 클라우드 컴파일은 BepInEx 5.4.23.2와 UnityEngine.Modules 2021.3.33 참조를 사용합니다. 게임 참조 스텁을 만들거나 게임 파일을 패키지에 넣지 않습니다.
- **미검증:** 0.3.0의 실제 게임 빌드·화면·표식·효과음·FPS, 재접속 후 효과 복원·실제 반동/피격·타 모드 조합. 메타데이터 대조와 모의 실행은 실제 플레이 검증을 대신하지 않습니다.

실제 적용 확인은 별도 테스트 프로필과 장비 사본으로 진행해야 합니다. 원본 수리 버프를 건드리지 않는 구조지만 다른 모드가 같은 계산 지점을 변경하면 별도 대조가 필요합니다.
